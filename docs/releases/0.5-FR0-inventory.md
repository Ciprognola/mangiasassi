# FR0 inventory — mapping the ground before the run-layer refactor (2026-09-28)

Read-only investigation. **No change to `index.html`.** FR0 (§10.6/§10.8) is the riskiest refactor left in
0.5 — this document exists so it can be specced precisely in Claude chat before any code moves.

## 1. Run-level state the maze keeps today

never partially mutated into existence), unless noted otherwise. "Reset" means "where it goes back to a
fresh value at the start of a new girone/run", not "cleared on death" (death only calls `resetActors`,
listed separately where relevant).

## 2. Run-level flows

- **`newRun(o)` / `RUN_START`** (S1, 0.4.5_11): Uomo roccia's «Nuovo gioco»/«Hardcore» opens the game-chooser
  modal (`RUN_GAMES`); Algidone skips straight to `RUN_START.maze`. Today only `RUN_START.maze` exists
  (`o=>startGame(false,o)`); `RUN_GAMES`'s `"ferma"` entry is `enabled:false` until FR1 gives it a
  `RUN_START.ferma`.
- **`startGame(resume, opt)`**: the one function that creates or resumes a maze run. Non-resume branch builds
  a fresh `G` (see table above); resume branch deep-clones `S.quick` and applies a long list of
  migration defaults field-by-field (this is exactly the pattern FR0 needs to either keep or centralise).
- **Girone clear → next girone**: inline in `update()`'s `"clear"` state branch — girone++, the two
  persistent-flag unlocks (`g5`/`sec`), the career-gironi increment, both girone achievements, lives refill
  (soft mode only), next map pick, `resetActors()`, `girPts`/`girBonusTxt` reset, `bjAfterClear()`. This one
  ~180-character line is the single most run-layer-relevant spot in the whole file — everything a run layer
  would want to own or hook into is packed into it.
- **`bjAfterClear()`**: decides El Gamblador vs. Ferma-invite vs. plain interlude card after a girone clears
  (girone 5 guaranteed El Gamblador, then flat 15%/girone for either; Ferma is forced from girone 8 if the
  player has never seen it). Reads `G.stage`/`G.dev`, calls into `faInvite`/`startGamblador`/`miniInterlude`.
- **`finishRun(o)`**: the only place a maze run *ends*. Computes sordi/exp from `G.score`/`G.stage` via
  `limiter`+`DIFF.mult`+`.7`, fires 4 achievements, clears `S.quick`, calls `persist()`+`cloudFlush()`, sets
  `G=null`. `o.quiet` (abandon) skips the "Partita finita" screen and toasts instead. **This is the only
  function that nulls `G`** — every other exit path (menu, pause, Ferma round trip) leaves `G` alive.
- **`quicksave()`**: `JSON.parse(JSON.stringify(G))` with `last` deleted and a live Super Panino merge split
  first. Called from exactly one place today (pause menu's "Salva ed esci"). Resume is `startGame(true)`.
  "Gioco corrente" (`tileAction("cur")`) is just `startGame(true)`.
- **`nextMinigame()`/`miniInterlude()`**: the interval card between gironi. `nextMinigame()` reads `G.game`
  (via `runGameOf`) so the card always names *this run's own* minigame (S1 fix) — before S1 it was
  hardcoded to Mangiaroccia's own card regardless of which game was running.
- **El Gamblador round trip**: `bjAfterClear()` → `startGamblador({run:true})` (reads `G.score` as the
  buy-in) → play mutates `G.score` directly during hands (not inventoried line-by-line here, out of scope)
  → `bjExit()` returns to `screen="game"`, `G.state="ready"` if `run` was true.
- **The professor hook**: winning "Roccia no"'s battle calls `startGame(false,{stage:3,score:M.reward})` —
  a **brand-new run**, not a resume, seeded at girone 3 with the battle reward as starting score. That
  seeded score is deliberately excluded from `girPts` (confirmed by `test_m1b.py`), so the M1b bonus never
  multiplies it.
- **The Ferma encounter round trip**: `bjAfterClear()` → `faInvite(o)` (shows the invite card; "Non ora" is
  hidden once forced) → accept → `S.p.fa.enc++` (persisted immediately, before the floor is even played) →
  `startFerma({run:true,encounter:n,mult5,...})`. Inside Ferma: `faClear(fl)` fires achievements per floor
  (only when `faReal()` — a real, non-dev, non-SIM, non-test encounter); the *last* floor's `faWinPanel()`
  calls `faEncPay()`, which adds `FA.cnt.base+FA.cnt.bonus` **directly to `G.score`** — the one and only
  place Ferma reaches back into the maze's own run state. Declining, or finishing (win or lose), both funnel
  through `faExit()` → `faBackToMaze(mult5)` → `faResume(mult5)` → either the interval card (if the girone
  was a multiple of 5) or straight back to `G.state="ready"`.
- **Dev jump**: `devJump(n, mi)` is a *parallel* run creator, not a variant of `startGame` — its own `G=`
  literal (no `game`/`girPts`/`girBonusTxt` fields at all; several are only ever set defensively elsewhere,
  e.g. `girPts` first appears the moment a pellet is eaten). `G.dev=true` gates persistence almost
  everywhere else in the file. A run layer will need `devJump` to build the *same* shape as `startGame`,
  or the dev/real code paths will keep silently diverging the way `girPts`'s absence from `devJump`'s
  literal already has (harmless today only because every read site guards with `||0`).

## 3. The Ferma side today

**What FA keeps that a run layer would plausibly own once Ferma becomes a *primary* run (FR1a), not just an
encounter inside a maze run:**
- `FA.score` — Ferma's own running score for the *current floor sequence*, separate from `G.score` even
  during a real encounter (only reconciled into `G.score` once, at `faEncPay()`, on the last floor).
- `FA.lives` — Ferma's own lives, a completely separate pool from `G.lives`, with its own respawn rule
  (`faFinishDeath`, 2s invulnerability, no "keep vs. reset" split like the maze's `keep` parameter).
- `FA.level` (floor index) — Ferma's own progression counter, analogous to `G.stage` but not unified with it
  in any way today; §10.6's planned "girone g plays level `(g−1) mod 3`" mapping does not exist yet.
- `FA.enc` (`{n,run,dev,mult5}` — *not* the persistent `S.p.fa`) — the current encounter's own parameters,
  created fresh by `faInvite`/`startFerma`, read by `faReal()`/`faClear()`/`faEncPay()`/`faExit()`.

**What must stay Ferma-only regardless of FR0** (climbing-specific, no maze equivalent to unify with):
`FA.p` (physics body: position/velocity/climbing/onGround), `FA.items` (thrown-object list), `FA.kick`
(win/collapse animation state machine), `FA.lv`/`FA.level` map data, `FA.stock` (the eaten-stock meter that
§10.6 plans to replace with the time-bar mechanic), `FA.paused`/`FA.state` (Ferma's own state machine,
parallel to but distinct from `G.state`), `FA.inv` (post-death invulnerability), `FA.raf` (Ferma's own
render loop handle — maze and Ferma each drive their own `requestAnimationFrame`, never shared).

## 4. Proposed run-layer shape and chunk split

**Proposed shape** — a `RUN` object, separate from both `G` and `FA`, that either game's own state object
embeds or points back to (exact composition is a [Q] below, not decided here):

```js
RUN = {
  game: "maze" | "ferma",      // which RUN_START/RUN_GAMES entry this is
  girone: 1,                    // renames G.stage / FA.level's future equivalent
  score: 0,                      // the ONE score both games read/write (replaces G.score and faEncPay's reach-in)
  girPts: 0, girBonusTxt: null,  // survives as-is, just relocated
  lives: 3, hard: false,
  char: "roccia", diff: "medium",
  flags: { g5:false, sec:false },        // mirrors of the S.p persistent flags the run cares about this session
  career: { girIncrement: fn },          // the hook that used to be the inline c0.gir++ / ach("clear"/"stage") calls
  encounter: null,                        // {kind:"gamblador"|"ferma", ...} while a sub-game is borrowing the screen
  dev: false,
}
```

Hooks §10.6 asks for (`onGironeClear`, quicksave, `finishRun`) become methods or free functions taking
`RUN` instead of `G` directly — the maze's own map/ghost/pellet state and Ferma's own physics/level state
stay *outside* `RUN`, each still owned by `G`/`FA` respectively, with `RUN` embedded inside each (`G.run`
Ferma equivalent `FA.run`) rather than `RUN` trying to hold game-specific fields itself.

**Suggested split into 3 thin chunks**, each independently testable against "no behaviour change":

- **FR0a — the object + maze reads through it.** Add `RUN` (or `G.run`) alongside the existing fields
  *without removing them yet* (dual-write: every write to `G.stage`/`G.score`/`G.girPts`/`G.lives` also
  updates the mirror). Change *read* sites one at a time to go through `G.run.*` and diff behaviour.
  Golden checks: re-run `test_m1a.py`, `test_m1b.py`, `test_b2.py` unchanged (they exercise girone
  progression, ghost setup and the bonus calc most heavily); a new smoke test asserts `G.run.stage===G.stage`
  etc. stay in sync for the length of a played-out girone.
- **FR0b — quicksave/resume and `finishRun` through it.** Once reads are migrated, retire the duplicate
  fields, updating `quicksave()`/`startGame`'s resume branch/`finishRun` to serialise/read `RUN` instead.
  Golden checks: `test_f2b.py` (quicksave/cloud save round-trips — the biggest existing suite touching
  persisted run shape), a new "old-shaped quicksave migrates" test mirroring `test_m1b.py`'s existing
  "no girPts field" case but for the whole `RUN` object at once.
- **FR0c — the girone-clear hook + career/achievements.** Extract the inline girone-clear line's
  side-effects (`c0.gir++`, the two `ach()` calls, `g5`/`sec` unlocks) into one `onGironeClear(RUN)` function
  the maze calls today and Ferma (FR1a) will call once it has its own girone concept. Golden checks: the
  achievement/career-counter assertions already scattered across `test_m1a.py`/`test_u4.py`'s career-modal
  checks, plus a new direct test calling `onGironeClear` twice and confirming `c0.gir` advances exactly once
  per call (guards against the eventual Ferma call site double-counting).

Each chunk should ship as its own build per §6 rule 3, with the full regression list from its "golden
checks" line re-run before commit, exactly like every E-series chunk this phase.

## 5. Risks and [Q] for the owner

- **[Q] Composition, not extraction**: should `RUN` be a field *on* `G` (`G.run`) and, later, *on* `FA`
  (`FA.run`), or should `G`/`FA` become fields *on* `RUN` (`RUN.maze`/`RUN.ferma`)? The table above assumes
  the former (smaller diff, `G` keeps existing); the latter is more "correct" long-term (§10.0's own
  sandbox goal — one run layer, pluggable game bodies) but touches every `G.` reference in the file, a much
  bigger blast radius than FR0a/b/c above assume. This decision changes the whole chunk split's size.
- **[Q] `G.stage` rename**: dozens of call sites read `G.stage` directly (`pickMap`, `mapClassOf`,
  `stagesForClass`, the ghost speed formula, achievements, HUD). Does FR0a rename the field itself
  (`G.stage`→`G.run.girone`, a mechanical but wide-reaching find-replace) or keep `G.stage` as a live alias
  that mirrors `G.run.girone`? Renaming is cleaner for the sandbox goal; aliasing is a smaller diff per
  chunk but means two names for one concept until a later cleanup pass.
- **[Q] Where does `onGironeClear` actually fire for Ferma?** Today Ferma has no girone concept at all —
  §10.6 says "girone g plays level `(g−1) mod 3`". Does FR1a's Ferma call `onGironeClear` once per **loop
  of 3 floors**, or once per **floor**? The career-gironi counter and Percorso tiles would count very
  differently depending on the answer, and this document can't infer intent from code that doesn't exist
  yet.
- **[Q] `El Gamblador`'s direct `G.score` mutation during play** was out of scope to trace line-by-line here
  (§2) — if `RUN.score` replaces `G.score` outright, every blackjack win/loss line that touches `G.score`
  needs to move too, in whichever FR0 chunk retires the field. Worth a quick separate grep pass before
  FR0b is scoped, so it isn't discovered mid-chunk.
- **Risk — dual-write drift (FR0a)**: keeping old and new fields in sync manually invites exactly the kind
  of silent one-tick lag bug found twice already this phase (E5a's `t:0` placeholder, E6a's bot decision
  timing). Recommend a single small assertion helper (`console.assert` or a dev-only check) that fires if
  `G.stage!==G.run.girone` etc. during FR0a's own testing window, removed once FR0b retires the duplicates.
- **Risk — `devJump`'s shape has already drifted from `startGame`'s** (§2, no `girPts`/`girBonusTxt`/`game`
  fields in its own literal, silently patched over by `||0`/`||null` guards at every read site). FR0 is a
  natural point to unify the two creation paths onto one shared "build a fresh run" helper — recommended,
  not required, but doing it *inside* FR0a is cheaper than doing it as a separate later chunk once `RUN`
  already exists in two slightly different shapes.
- **Risk — `S.p.fa`'s `enc` counter increments on *accepting* the invite, before the floor is even
  played**, while `faClear`'s achievements fire per floor *cleared*. A run layer that wants Ferma's
  eventual `RUN.girone` to mean "gironi survived" (matching the maze's own `G.stage++`, which only
  increments on a real clear) must not confuse it with `S.p.fa.enc` (accepted, not necessarily cleared) —
  flagging so FR1a's spec keeps the two concepts explicitly separate.
